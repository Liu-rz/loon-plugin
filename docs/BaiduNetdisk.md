# 百度网盘 Loon 去广告插件

根据手机百度网盘抓包编写的定向规则。当前分析了两次抓包（分别 6 条和 8 条请求）。初版用户反馈仍有开屏广告；当前 r2 改为两个广告主机的精确域名拦截，尚待真机复测，不保证去除开屏、信息流等全部广告。

## 安装

在 Loon 的「插件」中添加下面的订阅地址：

```text
https://raw.githubusercontent.com/Liu-rz/loon-plugin/main/BaiduNetdisk.plugin
```

启用插件和 Loon 连接，使用「规则分流」模式。两个广告主机由 `[Rule]` 中的 `DOMAIN` 规则拦截，无需 MITM 证书。若主配置中有更优先的直连或代理规则，可能影响插件规则命中，请以 Loon 请求记录中的实际匹配规则为准。

投屏广告开关修改仍需启用 URL 重写和 MITM，并安装、信任 Loon 的 CA 证书。当前只为 `conf.hpplay.cn` 声明 MITM。使用兼容的传统重写语法；JSON 响应替换要求 Loon Build 729 或更新版本。

更新后退出并重新打开百度网盘再验证；投屏配置若有本地缓存，可能需要等配置重新获取。若广告仍出现，可对出现广告的操作补充抓包，以继续定位。

## 处理范围

| 接口 | 处理 | 抓包依据 |
| --- | --- | --- |
| `sdk.1rtb.net`（捕获路径 `/sdk/req_ad`） | 精确域名 `REJECT`，覆盖该主机所有路径 | 两次样本均出现广告请求，响应为不透明二进制内容，不猜测其无广告响应格式 |
| `sdklog.zhangyuyidong.cn`（捕获路径 `/sdk/lurl`） | 精确域名 `REJECT`，覆盖该主机所有路径 | 参数包含竞价价格、广告位、竞价失败原因等 |
| `conf.hpplay.cn/sender/conf` | 将 `data.csj_ad_switch.enabled` 改为数字 `0` | 原始 JSON 中该字段为数字 `1`，其他投屏配置保持原样 |

r2 对上述两个完整广告主机整域拒绝，不扩展到父域或子域；投屏规则仍限定接口路径。域名拦截范围比初版更广，其他 App 使用这两个主机的广告 SDK 时也会受到影响。

抓包中的 `pop.pcsnetwork.netdisk.baidu.com/pop/probe_v6_addr` 为连接探测，`180.76.76.200/v4/resolve` 为解析请求，均不处理。没有对会员、下载权限、速度或账号字段做修改。

## 验证与限制

- 离线核对：第一份样本中 2 条广告请求匹配域名拒绝规则、1 条配置匹配响应规则、其余 3 条不匹配；第二份样本分别为 2、1、5 条。这里只验证规则匹配，不代表已在 Loon 真机生效。
- 第二份样本未发现新增广告主机或路径，广告获取仍返回 200，投屏广告开关仍为 1。不能据此确定是配置、抓包工具的流量接管方式、缓存还是其他原因导致初版未生效。
- 原始投屏配置确实存在目标字段，且其类型为数字；规则只替换这个字段。
- 拒绝广告请求后 App 是否重试、是否存在广告占位或等待时间，需要真机确认。若投屏异常，可先关闭插件排查。
- HTTPS 证书固定或未信任 MITM 证书时，投屏配置修改可能无法正常执行；两个广告主机的域名规则不依赖 HTTPS 解密，但仍需流量经过 Loon 且规则命中。

## r2 更新后验证

1. 在 Loon 刷新订阅，确认插件描述包含「更新版 r2」。
2. 开启 Loon，选择规则分流模式。先停止其他会接管 VPN 流量的抓包工具，再从后台退出并重新打开百度网盘。
3. 在 Loon 的请求记录中查找 `sdk.1rtb.net` 和 `sdklog.zhangyuyidong.cn`，检查匹配策略是否为 `REJECT`。若命中其他策略，提供脱敏记录继续排查规则优先级。
4. 如果广告主机已被拒绝但仍有开屏广告，可能还涉及缓存或其他广告来源，需要结合出现广告时的 Loon 请求记录继续定位。先不要删除 App 或清理网盘文件。

原始 HAR 未提交：其中可能含有令牌、设备标识、签名等敏感数据。仓库仅保留去除敏感参数后的接口信息。

语法依据：[Loon 重写文档](https://nsloon.app/en/docs/Rewrite/)、[插件格式](https://nsloon.uk/tutorial/advanced/Plugin_Format.html)。
